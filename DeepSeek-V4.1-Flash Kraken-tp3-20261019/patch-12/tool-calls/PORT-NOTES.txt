  encoder + tokenizer wrapper: ported as is (final assistant message gets a new assistant turn by default;
  add_generation_prompt=false leaves the prompt open-ended; continue_final_message leaves the final assistant
  message without EOS, reasoning left open when it ends inside reasoning; no final assistant -> 400).

Reconciliation with the BRRR tool-message reorder patch
-------------------------------------------------------
BRRR's "renderer tool-loop fix" (patch-brrr/stage1.patch, image layer 2026-11-01) touches two files:
  1. tokenizers/deepseek_v41_encoding.py: find_last_user_index skips tool-result-only user turns. Byte-identical in
     intent and code to #62199's encoder change -> kept unchanged, now documented as such. The overlay's encoder is
     BRRR's file + the #62729 hunks; nothing of BRRR's is reverted.
  2. renderers/deepseek_v4.py: reorders the raw OpenAI messages into the encoder's merged/sorted order
     (merge_tool_messages + sort_tool_results_by_call_order) before parse_chat_messages, so images inside tool
     results are collected in prompt order. Upstream solved the same problem differently (#60792 image_order /
     _image_indices). Since #62199/#62729/#64971 do not touch the renderer and do not depend on image_order, the BRRR
     renderer stays as baked (NOT overlaid) and upstream image_order is NOT ported. Both intents hold: tool results
     render in call order (checked against the 1017 reference with out-of-order results) and the encoder's
     generation controls see the same final message (the reorder only permutes tool results inside one tool block;
     assistant messages never move). Checked through the baked renderer itself (test_brrr_renderer_*).
     The encoder re-sorts idempotently, so prompts are unchanged by the reorder.
